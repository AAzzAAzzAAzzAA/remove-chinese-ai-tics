# 语义、事实与声音保真

去口癖是编辑任务，不是重新创作。改写前后应能建立可审计映射：每个新增事实有来源，每个删除片段不承载必要信息，每个语气变化都服务用户指定目标。

## 不变量清单

按文本类型选择需要锁定的字段：

| 类型 | 必须锁定 |
|---|---|
| 通用文章 | 人物、组织、地点、日期、数字、事件、立场、因果、引语 |
| 技术文本 | 命令、路径、版本、参数、返回值、条件、错误、依赖、风险、回滚 |
| 学术文本 | 研究问题、样本、方法、数据、显著性、引用、限定、结论范围 |
| 商务文本 | 指标、用户分群、假设、责任主体、期限、成本、承诺、优先级 |
| 新闻采访 | 来源归属、直接引语、时间线、观察与推断边界 |
| 创意写作与互动叙事 | 人物主权、协作创作权限、世界观、时间线、位置、物品、伤势、知识边界、视角、情节节点 |
| 私人消息 | 请求、边界、承诺、关系称呼、情绪强度、时间安排 |
| 高风险文本 | 适用地区、日期、概率、禁忌、责任范围、求助与警告 |

格式、长度、押韵、状态栏和模板字段在用户明确要求时也属于不变量。

## 句子级映射

对实质改写过的句子做内部检查：

- **保留：** 哪些事实或动作原样存在；
- **删除：** 删除的是否只有交付话术、重复、无证据升格或格式噪音；明确归属于作者/人物的主观评价本身是内容，不因“无证据”删除；
- **合并：** 被合并句之间是否真的同义；
- **推论：** 因果、比较和价值判断是否仍有原文依据；
- **语气：** 确定性、否定强度、礼貌、意外性和情绪是否发生变化；
- **范围：** “部分/通常/可能/必须”等限定是否被保留。
- **关系：** 纠错、排除、主次、递进、标量追加和对比焦点是否仍相同；
- **行动：** 自主性、意识状态、力度、速度和可察觉性是否仍相同；
- **归属：** 判断、评价、推测和立场仍属于原说话人或视角人物。

不需要向用户展示完整映射，除非用户要求审计或对照。

## 高风险语义变化

以下改动看似顺滑，实际容易改变含义：

### 否定范围

- “不一定能”不能改成“不能”；
- “并非所有”不能改成“都不”；
- “不是主要原因”不能改成“不是原因”。

### 纠错、对比与标量关系

- “不是 X，而是 Y”可能是纠错、排除、主次或重新定义；拆骨架前先锁定关系类型；
- 前文已经提出的错误命题 X 是纠错焦点，不能因直接陈述 Y 而消失；
- “不仅没道歉，还删了记录”含标量加重，不能改成没有强弱关系的普通清单；
- “真正的故障源在交换机”是具体定指，不等于金句式“真正的 X 从来不是 Y”。

### 模态与责任

- “可以”不等于“应该”；
- “建议”不等于“要求”；
- “计划”不等于“承诺”；
- “有望”不等于“将会”。
- “似乎/好像”可能标记证据不足，不能删成确定事实；
- “竟/竟然”标记预期落差，不能当程度副词清除；
- “不容置疑”可能表达认识确定性，“不容拒绝”可能表达强制权力，两者不能互换；
- 评价、许可、要求和推测的归属者不能从人物偷换成旁白或编辑者。

### 自主性、力度与速度

- “不由自主/下意识/无意识”与有意选择不同；新写时不应无依据添加，清理既有正文时则须把已断言的自主性当语义锁，无法等价重组就保留原词；
- “轻放、缓慢移动、几不可闻”若影响声响、暴露、伤势或物理结果，程度信息必须保留；
- 可察觉性与动作幅度不是同一维度，不能用“微微”替换“难以察觉”，也不能反向替换。

### 时间与频率

- “曾经、正在、长期、偶尔、通常、始终”不能因简洁而抹掉；
- 相对时间必须保留参照点；
- 版本和发布日期不能用“最新”替代。

### 因果与相关

- “同时发生”不能改成“导致”；
- “与……相关”不能改成“由……造成”；
- “用于解释”不能改成“证明”。
- “越 X 越 Y”必须保留变量方向、适用条件和原文是否主张因果；相关趋势不能被润色成因果规律。

### 引语与转述

- 直接引语不能润色后仍放在引号里；
- 转述要保留说话人和不确定性；
- 不把编辑者概括写成来源原话。

### 数量与范围

- “包括”不自动等于“仅包括”；
- “例如”后的项目不是完整清单；
- “多数”与“大量”不能互换；
- 单位、币种、百分比和区间必须逐字核对。

## 允许的最小动作

从风险最低到最高依次选择：

1. 删除模型身份、交付话术和未填占位符；
2. 删除完全重复的信息；
3. 删除编辑器添加或冒充客观结论的无证据评价，但保留事实句、明确归属的作者/人物立场和原有情绪强度；
4. 缩短冗余介词、连接词和抽象尾巴；
5. 合并同义句；
6. 恢复明确主语和直接动词；
7. 拆开模板句式、调整信息顺序；
8. 重排段落；
9. 重写整段或整篇。

能用前一项解决时，不使用后一项。

## 具体化边界

“把抽象写具体”只允许使用：

- 原文已经出现的事实和场景；
- 用户在当前任务中明确提供的信息；
- 已核实的外部来源，且任务授权检索；
- 纯形式性展开，如把已经列出的动作恢复为主谓句。

不得为了自然感补数字、案例、人物经历、气味、身体反应、动机、效果、评价或引用。缺细节时，宁可删掉空评价或报告证据不足。

## 声音保真

声音不是“有几个口头禅”。从原文已有证据中提取：

- 正式程度和称呼；
- 句子长短与停顿方式；
- 常用动词和抽象程度；
- 直接、回避、讽刺、克制或热情；
- 第一/第二/第三人称偏好；
- 对确定性和情绪的处理；
- 领域术语、圈层词和地域表达；
- 哪些内容会展开，哪些只点到为止。

保留声口不等于保留所有坏句子。优先保留有区分度且承担内容功能的特征；删除跨主题都能套用的模型化结构。

## 过度修正测试

终稿若出现以下现象，说明改过头：

- 所有句子都变短、都变口语；
- 正式文本被塞入“说白了、其实、你看”；
- 为打破三联结构而随机删掉必要第三项；
- 为变化节奏而制造碎句；
- 技术术语被换成不准确的日常词；
- 角色差异被改成编辑者自己的稳定声口；
- 所有隐喻、排比、连接词和礼貌表达都被清空；
- 谨慎限定被删除，结论反而更武断；
- 原文明确判断被“中立化”；
- 新增细节比原文更生动，却无法回指来源。

命中时回退到更小修改。

## 批量一致性

长包或多文件处理要单独维护：

- 术语表与专名表；
- 不可修改字符串；
- 角色/品牌/作者声音卡；
- 时间线和版本；
- 已知误判白名单；
- 已处理规则及其密度；
- 每个文件的异常和待确认项。

批量结束后做跨文件检查：同一术语是否被轮换、相同口癖是否从句子层转移到标题层、每篇是否被改成同一种结构、原有作者或角色差异是否仍在。

## 交付前最短校验

1. 抽查所有数字、专名、引语和否定句；
2. 搜索新增的绝对词、心理词和因果词；
3. 搜索模型身份、交付话术、占位符和 Markdown 残留；
4. 对比段落数量与信息点，不把删段误当去冗余；
5. 朗读一遍，确认节奏变化来自内容而非刻意参差；
6. 若无法证明某个新增细节来自输入，删除它。
